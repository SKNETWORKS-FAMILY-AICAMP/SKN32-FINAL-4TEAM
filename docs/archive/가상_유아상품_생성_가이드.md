# 가상 유아 상품 생성·DB 적재 가이드

이 프로젝트의 유아 상품 데이터는 추천·예산·수량·안전 검증 흐름을 테스트하기 위한 **합성 데이터**다. 실제 상품, 가격, KC 인증, 리콜 또는 구매 근거로 사용하면 안 된다.

기본 데모 카탈로그는 지원 품목군 18개에 생성 상품을 품목군당 10개씩 만들고, 유모차·카시트 등 검증 시나리오용 고정 상품을 더한 188개 레코드로 구성한다.

## 구성 요소

| 목적 | 스크립트 | 결과 |
|---|---|---|
| 범용 합성 상품 생성 | `scripts/generate_baby_products.py` | 임의 경로의 JSON 파일 |
| 서비스용 데모 카탈로그 구성 | `scripts/build_baby_catalog_demo.py` | `data/baby/catalog_demo_v1.json` |
| 카탈로그 DB 적재 | `scripts/seed_baby_catalog.py` | `catalog.*`, 가격 관측값 |
| 생성부터 DB upsert까지 일괄 실행 | `scripts/generate_and_seed_baby_catalog.py` | 위 데모 카탈로그를 DB에 upsert |

생성기는 고정 seed(`42`)를 사용하므로 같은 소스 코드와 데이터 사전에서는 같은 데모 카탈로그를 재현한다.

## 사전 준비

통합 시더는 `src.config`을 통해 프로젝트 루트의 `.env`에서 `DATABASE_URL`을 읽는다. 실행 전 대상 DB가 맞는지 확인한다. 운영 DB에 데모 데이터를 넣지 않는다.

```bash
# .env 예시
DATABASE_URL=postgresql://truefit:truefit@localhost:5432/truefit
```

새 빈 DB라면 먼저 스키마와 기준 데이터를 준비한다. `db/setup_all.py`는 `.env`를 직접 읽지 않으므로 셸 환경변수로 내보내야 한다.

```bash
set -a
source .env
set +a

uv run python db/setup_all.py
```

## 권장 방법: 생성·검증·upsert 일괄 실행

```bash
uv run python scripts/generate_and_seed_baby_catalog.py
```

이 명령은 다음을 순서대로 수행한다.

1. 카테고리별 합성 사양·가격·재고 데이터를 결정적으로 생성한다.
2. 서비스에서 사용하는 18개 품목군과 고정 검증 시나리오를 데모 카탈로그 형식으로 조합한다.
3. 레코드의 필수 필드, 단위, 가격, 재고 상태를 검증한다.
4. 상품·옵션·판매처·가격 관측값을 기존 `seed_catalog()` 규칙으로 upsert한다.

동일 상품과 가격은 재실행해도 중복 관측값을 만들지 않는다. 가격이 달라진 경우에는 기존 관측값을 덮어쓰지 않고 새 가격 관측값을 추가한다.

DB에 쓰지 않고 생성물과 입력 계약만 확인하려면 다음을 사용한다.

```bash
uv run python scripts/generate_and_seed_baby_catalog.py --dry-run
```

생성된 DB 입력 JSON도 별도 보관하려면 경로를 명시한다.

```bash
uv run python scripts/generate_and_seed_baby_catalog.py \
  --write-catalog /tmp/baby-catalog.json
```

`--write-catalog`은 지정한 파일을 갱신하므로, 보존할 파일 경로는 피한다.

## 단계별 실행

### 범용 데이터만 생성

아래 명령은 DB에 쓰지 않는다. 특정 카테고리와 수량으로 생성기를 실험할 때 사용한다.

```bash
uv run python scripts/generate_baby_products.py \
  --categories stroller,car_seat \
  --count 20 \
  --seed 42 \
  --output /tmp/baby-products.json
```

이 출력 형식은 범용 생성기 형식이므로 바로 DB 시더에 전달하지 않는다. DB에 적재할 데모 입력은 다음 명령으로 만든다.

```bash
uv run python scripts/build_baby_catalog_demo.py
```

그 뒤 별도 시더로 적재할 수 있다.

```bash
uv run python scripts/seed_baby_catalog.py \
  --corpus synthetic \
  --dataset-version baby-demo-v1
```

## 적재 확인

DB 접속이 가능한 환경에서는 준비성 검사와 카탈로그 테스트를 실행한다.

```bash
uv run python scripts/check_baby_readiness.py \
  --corpus synthetic \
  --provider unconfigured

uv run python -m pytest -q tests/test_baby_catalog.py
```

설명서 검색 provider나 게시된 설명서 매핑이 없다면 readiness 결과가 `partial`일 수 있다. 이는 카탈로그 upsert 실패와는 별개이며, 안전 검증이 필요한 상품은 자동 선택되지 않는다.

## 안전 데이터 원칙

- 실제 KC 인증번호나 실제 리콜 정보를 생성하지 않는다.
- 인증 정보가 없거나 검증되지 않았다면 `unknown`으로 남긴다.
- 테스트용 리콜·미확인 인증 사례도 합성 데이터임을 명시한다.
- 안전 검증이 통과하지 않은 후보는 추천 결과의 자동 선택 대상이 아니다.
