# 0003. 데모 화면에서 세트 신뢰도 · 회색축 문구 · 표시용 리뷰 수를 뺀다

- 날짜: 2026-09-14
- 상태: 채택 (해커톤 데모 범위, 2026-09-15)
- 관련: `src/engine/prompts.py` `explain_system` · `src/engine/stage5_explain.py` ·
  `src/services/review_service.py` `review_brief` · `src/services/recommendation_service.py` `memo_suggestion` ·
  `src/agent/result_agent.py` · 프론트 담당의 개발 요청(2026-09-14, "화면에 나가는 '없는 정보' 2건 제거")

## 맥락

원칙은 하나다 — **서버가 모르는 값은 화면에 보여주지 않는다.** 모르면 `null` 로 주거나 문장에서 뺀다. 프론트는
`null` 을 숨기고 0·"—"·추정값으로 채우지 않는다(프론트 `1d156aa` 가 그쪽 정리를 끝냈다). 서버가 만들어 보내는
값 셋이 이 원칙에 걸렸다.

1. **표시용 리뷰 수.** 관측 산출물에 없는 상품에 `_fallback_review_count`(상품 키 해시로 7~13)를 `total_count` 로
   냈다. 응답에 실측/표시용 구분이 없어 프론트가 거를 수 없었고, 장바구니·리뷰 패널·리포트에 "리뷰 13건" 이
   실측처럼 나갔다.
2. **추천 요약 속 세트 신뢰도.** `verify_build` 는 아직 규칙 스캐폴드(100 − 감점, RAG 미연결)라 0점 같은 극단값이
   나오고, 요약 첫 문장에 "검증 신뢰도는 0점입니다 … 낮은 만큼 유의해야" 가 붙었다. 신뢰도를 넣도록 강제한
   자리가 넷이었다 — 프롬프트 규칙 4(ko·en), LLM 입력의 `검증 신뢰도:` 줄, headline 에 숫자가 없으면 초안을 버리는
   가드, 규칙 템플릿 폴백(headline·summary). 요청서가 놓친 곳이 둘 더 있었다 — 확정 화면 메모 제안의
   "세트 검증 신뢰도 N점", 결과 에이전트 시스템 프롬프트의 "세트 검증 신뢰도: N".
3. **회색축 문구.** "확인이 필요한 것: 설명서·규격(RAG 미연결) 근거는 확인되지 않았습니다" 는 개발 상태 설명이지
   사용자에게 할 말이 아니다.

**규칙 4 는 하루 전(2026-09-13) 승인으로 넣은 것이다** — 그때 이유는 "headline 이 신뢰도 인용을 빠뜨린다"
(`docs/프롬프트_개선_초안_설명문장.md`)였고, 오늘 이유는 "신뢰도 자체가 보여줄 단계가 아니다" 다. 되돌리는 것이
맞지만 기록 없이 되돌리면 다음 사람이 같은 이유로 다시 넣는다.

## 검토한 대안

| 대안 | 판단 |

| **문장·입력·가드·폴백에서 전부 뺀다. 값은 `verification.confidence` 필드와 엔진 로그에 남긴다** | **채택.** "보존해야 하면 따로 보존" — 사용자 문장과 데이터를 분리 |
| `_BANNED_IN_DRAFT` 에 "신뢰도" 를 넣어 막는다 | 기각. 입력에 신뢰도가 있는 한 모델이 계속 인용하고 초안이 전부 폴백으로 떨어진다(요청서 의견과 같음) |
| 표시용 리뷰 수 대신 `parts_asin_map.csv` 의 아마존 `rating_number` 를 낸다 | 기각. 관측 산출물의 리뷰 수(같은 상품 197건, 2023-09 까지 본문 있는 리뷰)와 척도가 달라(3,364) 한 화면에 섞이면 더 헷갈린다 |

| 리뷰 관측 caveat("상품 단위 신호이며 개별 리뷰의 진위가 아닙니다")도 같이 뺀다 | 이번 범위 밖. 03 리뷰 슬라이드의 면책 한 줄(`cleansing_summary`)이 같은 뜻을 쉬운 말로 내고 있어 다음 정리 후보 |

## 결정

1. `review_brief` 는 리뷰 수를 모르면 `total_count: null`. `_fallback_review_count` 삭제. `ReviewBriefOut.total_count` 는
   `int | None`.
2. 추천 요약에서 신뢰도를 뺀다 — 규칙 4(ko·en)와 규칙 2 의 신뢰도 단위 문장, LLM 입력의 신뢰도·회색축 줄, 신뢰도
   누락 재시도 가드, 폴백 headline·summary 의 신뢰도 문구, 영어 지시문(`lang.py`)의 "Say 'confidence 94'".
   확정 메모는 "세트 검증 쟁점 있음 — 추천 과정 보기에서 확인" 으로, 결과 에이전트 프롬프트는 쟁점만.
3. 회색축 caveat 를 사용자 문장(`explanation.caveats` → `explanation_text`)에서 뺀다. 엔진 로그에
   "근거 미확인 축(화면에는 안 나감)" 으로만 남긴다.
4. **보존:** `verification.confidence` 필드·DB(`measured_values.confidence`)·재탐색 흐름은 그대로. 회색축은
   `VerificationTarget.gray_axes` 와 [5] 콘솔 로그에. 뺀 문안은 아래에 적어 둔다.

## 대가

- 요약에서 "이 구성이 얼마나 검증됐는지" 를 말할 수단이 없어진다. 신뢰도 계산 공식이 생기고 RAG 가 연결되면
  규칙 4 를 다시 넣되, 그때는 **입력에 값을 넣는 것과 규칙을 같이** 넣는다(입력만 넣으면 모델이 멋대로 인용한다).
- 리뷰 산출물이 없는 부품은 장바구니·리포트에 "리뷰 정보 없음" 으로 비어 보인다. 데모가 덜 채워져 보인다 —
  가짜 숫자보다 낫다는 것이 0001 과 같은 판단이다.
- 회색축 정보가 화면 어디에도 없다. 검증이 무엇을 못 봤는지는 지금 콘솔 로그로만 안다.
