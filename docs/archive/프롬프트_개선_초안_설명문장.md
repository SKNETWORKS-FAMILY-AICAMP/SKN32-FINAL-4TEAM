# 프롬프트 문안 개선 초안 — [5] 추천 설명 문장 (팀 승인 요청)

**대상 파일:** [src/engine/prompts.py](../src/engine/prompts.py)의 `EXPLAIN_SYSTEM`.
**근거:** 기획서 §19-3 체크리스트 미승인 항목. `src/CLAUDE.md`: "문안 변경은 팀 승인 대상이다 —
임의로 고치지 말고 사용자에게 확인한다." **이 문서는 초안이며, 아직 `prompts.py`에 반영하지
않았다.** 승인 후 반영한다.

## 실호출에서 드러난 약점 둘

`MOCK_MODE=0`으로 실제 OpenAI 호출을 확인하는 과정에서 발견. (참고: 이번 세션에는 그때
받은 원문 응답 로그가 남아 있지 않다 — 재현하려면 `.env`에 키를 넣고 `MOCK_MODE=0`으로
`main.py computer_pass`를 다시 돌려 확인해야 한다.)

1. **headline이 검증 신뢰도 인용을 빠뜨리는 경우가 있다.** 현재 규칙 4("예산 사용액과 검증
   신뢰도는 입력값 그대로 인용합니다")는 "인용한다"고만 지시할 뿐 **숫자가 실제로 문장에
   들어가야 한다는 걸 예시로 못 박지 않는다.** `stage5_explain._llm_draft`는 slot 집합·금지어·
   타 슬롯 이름 인용만 검사하고([stage5_explain.py:125-132](../src/engine/stage5_explain.py#L125-L132)),
   신뢰도 숫자가 headline에 들어있는지는 검사하지 않는다 — 빠져도 그대로 채택된다.

2. **"강력한 성능" 같은 평가 표현이 섞인다.** 규칙 7("과장·마케팅 표현을 쓰지 않고, 좋다·
   준수하다 같은 평가 대신 사실을 씁니다")이 "좋다·준수하다" 두 예시만 들고 있어 모델이
   "강력하다·뛰어나다·최고의" 같은 동의어로 우회한다. `_BANNED_IN_DRAFT`
   ([stage5_explain.py:24](../src/engine/stage5_explain.py#L24))는 `score`·`점수`·지시문 베끼기만
   걸러내고 평가어는 걸러내지 않아 **후처리 검사도 통과한다.**

## 제안 — 문안 변경 (승인 대상)

### 규칙 4 (headline 신뢰도 인용) — 예시를 못 박는다

**현재:**
```
4. headline: 구성 전체를 요약하는 완결된 문장 한두 개를 직접 작성합니다. 이 지시문의 문구를 그대로
   옮겨 적지 않습니다. 예산 사용액과 검증 신뢰도는 입력값 그대로 인용합니다.
```

**제안:**
```
4. headline: 구성 전체를 요약하는 완결된 문장 한두 개를 직접 작성합니다. 이 지시문의 문구를 그대로
   옮겨 적지 않습니다. 예산 사용액과 검증 신뢰도는 입력값 그대로 인용하며, **검증 신뢰도 숫자는
   반드시 "신뢰도 92점"처럼 headline 문장 안에 그대로 등장해야 합니다.** 신뢰도를 언급하지 않는
   headline은 만들지 않습니다.
```

### 규칙 7 (평가어 금지) — 구체적인 금지어를 나열한다

**현재:**
```
7. 한국어 존댓말. 과장·마케팅 표현을 쓰지 않고, 좋다·준수하다 같은 평가 대신 사실을 씁니다.
```

**제안:**
```
7. 한국어 존댓말. 과장·마케팅 표현을 쓰지 않습니다. "좋다·준수하다·강력하다·뛰어나다·최고의·
   압도적인·완벽한·훌륭한" 같은 평가어 대신, 이미 입력에 있는 수치·순위·가격 같은 사실만 씁니다.
   품질을 평가하고 싶어지면 그 대신 "N순위"·"동급 대비 M원 절감" 같은 입력값을 그대로 쓰세요.
```

## 제안 — 코드 가드 추가 (문안과 별개, 팀 승인 불필요 영역이라고 판단되면 바로 반영 가능)

문안만으로는 모델이 규칙을 어겨도 걸러낼 수단이 없다. `stage5_explain.py`는 우리 소유 파일이라
아래 둘은 **문구 승인과 무관하게 코드 안전장치로 바로 넣을 수 있다고 보는데, 확인 부탁한다:**

1. `_BANNED_IN_DRAFT`([stage5_explain.py:24](../src/engine/stage5_explain.py#L24))에 평가어
   목록을 추가 — `"강력", "뛰어나", "최고", "압도적", "완벽", "훌륭"` 등. 이미 있는 매커니즘
   그대로(걸리면 `None` 반환 → 규칙 템플릿 fallback)라 위험이 적다.
2. headline에 `tgt.confidence` 숫자 문자열이 없으면 draft를 버리고 규칙 템플릿으로 내리는
   검사 한 줄 추가 (`_llm_draft` 반환 직전, 132번째 줄 근처).

두 검사 모두 **문장의 표현을 바꾸는 게 아니라 규칙 위반을 잡아내는 것**이라 문안 승인 절차와는
결이 다르다고 판단했는데, 팀 기준에서 "문안 변경"으로 봐야 하면 이 문서에 같이 포함해 승인
받겠다.

## 확인 요청 사항

1. 규칙 4·7 문구 변경안 승인 여부 (또는 다른 표현 제안).
2. 코드 가드 두 가지를 문안 승인과 별도로 바로 넣어도 되는지, 아니면 이것도 같이 승인 받아야
   하는지.
3. 실제 응답 예시가 필요하면 `.env` 키로 재현해서 첨부할지 (현재는 규칙 위반 지점만 코드로
   추적했고 실제 발화 원문은 없음).
