## 인정하는 결과

설정 테스트는 직접 SQL로 설정한 JSON이 유지/삭제되는지 확인한다. 사용자 설정 편집 HTTP 기능을 검증한 것은 아니며, 보고서가 이 경계를 밝힌 것은 적절하다. 기존302건 전체 통과는 이전 DB 기록으로 보존한다.

## 보완 사항

### R1 — 비밀번호 변경과 동시 로그인 사이의 토큰 무효화 경합

UserRepo.update_password는 password_updated_at=now()를 사용한다. PostgreSQL now()는 트랜잭션 시작 시각이며 실제 비밀번호 교체 완료 시각이 아니다. auth_service.login/change_password의 사용자 조회도 FOR UPDATE 없이 수행한다.

비밀번호 변경 트랜잭션 시작 뒤 변경 커밋 전 다른 요청이 기존 비밀번호로 로그인하면, 발급 iat가 password_updated_at보다 나중일 수 있다. 이 토큰은 변경 후에도 현재 `iat <= password_updated_at` 검사에서 거부되지 않는다. 오래된 해시를 먼저 읽은 로그인 요청이 변경 후 토큰을 발급하는 순서도 막지 않는다. float 정밀도와 동등 비교만으로 동시성은 보장되지 않는다.

수정: 로그인 성공 판정·비밀번호 변경/탈퇴를 같은 사용자 행의 잠금/버전 재확인으로 직렬화하고 실제 변경 순서에 맞는 발급/무효화 시각 정책을 적용한다. now()를 다른 시계 함수로 바꾸는 것만으로 오래된 비밀번호 조회 경합이 해결되는 것은 아니다. 별도 연결 두 개로 변경 도중 기존 비밀번호 로그인, 변경 후 새 비밀번호 로그인, 동시 변경을 검증한다. 기존 토큰 거절과 새 로그인 쿠키 사용 성공을 둘 다 확인한다.

### R2 — D6 경계 테스트의 “사용 가능한 새 쿠키” 검증 부족

test_d6_iat_boundary_rejects_token_at_password_change_and_relogin_works는 재로그인200 및 쿠키 존재만 확인하고 그 클라이언트로 /auth/me를 호출하지 않는다. 보고서의 “usable replacement cookie” 주장을 이 사례만으로 증명할 수 없다. 또한 Python float iat를 DB timestamptz로 저장하면 마이크로초 정밀도로 반올림되므로, 저장 시각과 원래 float가 정확히 같다는 보장도 없다.

수정: DB에서 실제 저장한 경계 시각을 읽어 정확히 그 iat로 서명한 테스트 토큰을 구성하고 equality 거부를 확인한다. 재로그인한 동일 클라이언트의 /auth/me 성공을 추가한다. 기존49건 전체 반복 대신 이 변경 경계만 확인한다.

### R3 — Origin/mutation 정책 미구현 및 브라우저 검증 미완료

보고서가 명시한 대로 P6 RULES의 Origin/mutation 정책은 아직 구현되지 않았다. 이는 보고서에서 누락하지 않은 미충족 조건이다. 공통 middleware 파일이라는 이유만으로 P6 완료 조건에서 삭제할 수는 없다. P1/공통 인증 경계와 담당 범위를 맞춰 구현하고 허용 출처/거부 출처의 쿠키 변경 요청을 검증한다. 실제 브라우저 smoke는 P5 산출물 확보 후 수행하도록 기존 조건을 유지한다. 지금 가능한 DB 인증·후기 권한 작업 전체를 그때까지 중단할 필요는 없다.

## 보고서 정리

현재 src/auth/jwt.py에도 문서 변경이 있으므로 changed_files와 실제 변경 범위를 맞춘다. 과거 재현 안내의 “setup_all로 DB를 다시 만든다”는 표현은 부정확하다. setup_all은 멱등 설치/시드이며 테스트가 남긴 고정 이메일을 삭제하지 않는다. 전용 새 DB 또는 테스트 데이터 정리 방식으로 재현 조건을 명확히 한다. 서비스 DB 미적용 자체는 P6 기술적 결함이 아니다.
