## 후속 구현자 계약

- P5는 **persist_baby_requirements의 반환값 또는 load_persisted_baby_requirements**를 P4에 전달한다. 한 UUID를 가진 소유·잔여 조각 두 개를 만들어 넘기지 않는다. 저장 전 pure 조각의 fulfilled_qty=None은 기존 전량 소유 조각 의미로만 지원한다.
- persisted requirement에는 총 required_qty와 explicit fulfilled_qty가 있다. 후보가 없어도 미보유 잔량을 누락시키지 않는다. 보유량이 포함된 요구사항에는 같은 재고를 owned_items로 중복 공급하지 않는다.
- P3 생산자는 CandidateCheck.requirement_id를 채운다. P4는 주어진 ID의 불일치를 거절한다. 기존 수동 fixture와의 호환을 위한 null은 유지하므로 P5는 HTTP 입력 대신 실제 후보 원장에서 연결 정보를 공급해야 한다.
- 예전 P4 보고서의 카시트/기저귀/물티슈 자동 선택 및50만원 feasible 결과는 수정 전의 무해당 규칙에 의존했다. 현재 규칙 미검토 품목은 자동 선택할 수 없다. 검토된 제품군별 적용/무해당 근거를 추가한 뒤 새 통합 결과를 기록해야 한다.
- 기존 match_spec.pieces만 가진 과거 필요 품목은 P5 실행 시작 시 build→persist로 새 계약을 저장한다. 새 loader는 baby_requirement 계약이 없는 행을 반환하지 않는다.
