원본 서비스 DB `localhost:5432/truefit`은0008까지 적용된 상태다. 원본은 읽기만 했으며 `p0_service_repro_20260913` 복제본에서 실패를 재현했다.

## 0009 중복 컬럼 오류 수정

과거0001/0004/0005 파일로 설치한 DB에는0009가 추가하는 email_verified_at, updated_at, ui_settings 및 set_updated_at 트리거가 이미 존재한다. 현재0009는 무조건 생성하므로 중복 컬럼 오류로 중단됐다.

`db/migrate.py`는 미적용0009에 한해 `db/compatibility/0009_existing_identity_fields.sql`을 실행한다. 기존 컬럼의 타입·NULL 허용·기본값 및 트리거의 함수·이벤트·조건·활성 상태가 요구 정의와 일치하는지 검증하고, 누락된 항목만 생성한다. 기존 값은 유지하며 불일치 정의는 명시적으로 거절한다. 기존 마이그레이션 파일 및 기록된 체크섬을 수정하지 않는다. 0009 완료 이력은 원본0009 체크섬으로 기록하고 콘솔에 호환 적용을 명시한다.

별도 DB 테스트 `tests/test_migration_0009_compatibility.py` 4건 통과: 신규/반복 적용 및 값 보존, 일부 컬럼만 있는 설치, 잘못된 컬럼 타입 거절, 비활성 기존 트리거 거절.

## 추가로 확인한 기존 데이터 문제

복제본은0009–0012를 통과한 뒤0013의 plan_revision_domain_snapshot_v1_check에서 중단됐다. 기존 계획5건에 definition={} 및 0으로 채운 content_hash가 들어 있다. 이 값을 현재 규칙으로 덮어쓰면 과거 실행 규칙을 복원했다고 잘못 표현하게 되므로 자동 보정하지 않았다.

원본에는 계정1건·계획5건·추천 실행3건이 있다. 원본0008 이력 유지 확인. 기존 자료 보존 여부 또는 새 DB 초기화에 대한 사용자 답변을 기다린다. 이 결정 전에는 실제 DB에 적용하지 않는다. 단순 재실행이나 checksum 기록 변경만으로 전체 설치를 완료할 수 없다.

기존0001/0004/0005 체크섬 경고는 실제 정의 차이의 기록이므로 숨기지 않는다. 이번 수정은 확인된0009 정의 중복만 처리한다.
