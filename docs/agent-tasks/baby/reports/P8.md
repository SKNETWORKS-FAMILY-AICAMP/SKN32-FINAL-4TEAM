# P8 v3 implementation record

## v3 DB alignment

Implemented the authenticated baby part-review write and publish path using the active develop `da79839` relation model: `evidence.review_subject` identifies the exact variant, `community.review` stores author/subject/current revision/status, and all user body/rating/moderation state is stored in `community.review_revision`. No old merged-review mapping, dataset SQL, or PostgreSQL RAG table was added.

`POST /reviews/part` validates rating, text size, variant existence, and scalar axis scores; selects the current baby `domain_version_id`; and persists a new draft revision. A re-edit invalidates matching ready aggregates by setting their status to `stale`. `POST /reviews/{id}/publish` checks ownership through the query itself (other users receive 404), approves the newest revision, and makes it the current published revision. The telemetry payload continues to be stored only under `usage_context.telemetry`.
